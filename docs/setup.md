# Lab setup

These instructions provide a reconstruction path, not an export of the original VM. Record your actual versions, VM resources, network mode and changes locally before publishing.

## Deployment checklist

Work through the stages in order and verify each stage before moving on. Commands below are examples for Ubuntu; follow the version-specific upstream instructions if they differ. Keep a private record of the VM version, assigned resources, network mode, Docker version, Wazuh release, n8n image version and agent version. Do not publish that record until it has been reviewed.

| Stage | Desired outcome | Verification |
| --- | --- | --- |
| VMware and Ubuntu | VM boots and has network connectivity | `hostnamectl`, `ip -br address` |
| Docker and Compose | Container runtime responds | `docker --version`, `docker compose version` |
| Wazuh | Manager, indexer and dashboard are running | `docker compose ps`, dashboard login |
| Endpoint | Agent is running and enrolled | `systemctl status wazuh-agent` and dashboard |
| n8n | Owner can reach workflow editor | Browser login on the configured address |
| Integration | Agent can request and summarize recent alerts | Test the query and compare output to source alerts |

## 1. Prepare VMware and Ubuntu

Create an Ubuntu VM in VMware Workstation, allocate sufficient CPU, memory and storage for Wazuh and n8n, and use a private or host-only lab network where practical. Consult the current [Wazuh Docker requirements](https://documentation.wazuh.com/current/deployment-options/docker/wazuh-container.html); a full stack needs more resources than an individual component. Take a VM snapshot before major changes. Install updates, Docker Engine and the Docker Compose plugin using their official instructions.

Before continuing, confirm the runtime is available:

```bash
hostnamectl
docker --version
docker compose version
```

Document the IP and network mode privately. Avoid exposing lab management interfaces to public networks.

## 2. Deploy Wazuh

Use the official [single-node Docker instructions](https://documentation.wazuh.com/current/deployment-options/docker/wazuh-container.html), including their version-matched repository checkout, `vm.max_map_count` prerequisite, certificate generation, and `docker compose up -d`. Change default credentials according to Wazuh's instructions. Wait for the manager, indexer and dashboard to become healthy, then inspect:

```bash
docker compose ps
```

The course also provides an [upstream lab setup](https://github.com/Atlantium-AI/wazuh-n8n-lab-setup); review scripts before running them. Avoid running two Wazuh stacks on the same ports.

## 3. Enroll an endpoint

In the dashboard, use **Deploy new agent** to generate the installation and enrollment command for your Ubuntu version. If the agent is on the same host as a containerized manager with the required ports published, loopback may be appropriate; use the reachable manager address for a different VM. Run the commands generated by the dashboard, then confirm:

```bash
sudo systemctl status wazuh-agent --no-pager
```

Confirm the endpoint appears connected in the dashboard. Names and ports depend on your deployment.

## 4. Configure auditd when used

```bash
sudo apt update
sudo apt install auditd audispd-plugins
sudo systemctl enable --now auditd
```

Inside the existing `<ossec_config>` element of `/var/ossec/etc/ossec.conf`, add the following only if an equivalent entry does not already exist:

```xml
<localfile>
  <log_format>audit</log_format>
  <location>/var/log/audit/audit.log</location>
</localfile>
```

Preserve the existing XML, check your version's documentation, and restart `sudo systemctl restart wazuh-agent`. Audit collection alone does not create all useful audit rules; add and test rules appropriate to your lab and policy.

## 5. Start n8n

Follow [n8n's Docker installation guide](https://docs.n8n.io/hosting/installation/docker/), configure persistent storage, and create the owner account. The demonstrated UI uses `http://localhost:5678`. Restrict access to your isolated lab; configure TLS and authentication for any remote access. Give n8n network access to the indexer using the actual hostname and port reachable **from the n8n container**. `localhost` inside a container refers to that container, not the Ubuntu host.

## 6. End-to-end verification

1. Confirm each service is ready and the endpoint is connected. Check logs with `docker compose logs --tail=100` from the appropriate Compose directory when needed; logs may contain sensitive data.
2. Confirm recent alerts are visible in the Wazuh dashboard. Record the query time range and verify that the Ubuntu VM clock is correct.
3. Test the indexer query independently using [workflow.md](workflow.md), then run the same bounded query through the n8n tool.
4. Submit a chat request, compare the model summary with the actual records, and document any missing evidence or incorrect inferences.
5. Export a sanitized copy of your own workflow and record the actual component versions.

## Troubleshooting

| Symptom | Checks |
| --- | --- |
| Dashboard is not ready | Allow startup time; inspect container status, resource availability, indexer logs and the `vm.max_map_count` prerequisite. |
| Agent is disconnected | Check agent service, manager address, enrollment and firewall rules; verify manager ports are reachable from the agent. |
| n8n cannot reach indexer | Test DNS and routing from the n8n network; `localhost` inside the container is not the host. Verify the indexer port, credentials and CA. |
| Certificate verification fails | Check the certificate chain, expiry and hostname against the URL. Trust the correct lab CA rather than disabling TLS checks. |
| No alerts returned | Check time synchronization, selected time range, index pattern, permissions and the dashboard for actual alerts. |
| Model response fails or misstates evidence | Check model credentials, service availability, tool output and context limits; compare any claims with source records. |

Continue with [configuration guidance](configuration.md) and [workflow and validation](workflow.md).
